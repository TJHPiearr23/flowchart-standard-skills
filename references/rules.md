# 绘制规范与自检清单

## 一、排版五大铁律

1. **单一入口、单一出口**：除连接符与汇合点外，主流程线只保留一条向下主线。一份流程图有且只有一个「开始」。
2. **流向一致**：一律自上而下、自左而右。折返箭头必须方向清晰，不得与主线混淆。
3. **文字精炼**：框内写动词短语（「计算总和」「校验密码」），不写句子。菱形内必须是问句（「密码正确？」）。
4. **分支必标注**：菱形引出的每条箭头都要标 是/否、Y/N、真/假 或具体条件值，**绝不能空白**。
5. **避免线线交叉**：优先重排；无法避免时用「小半圆跨线」或让一条线断开——不要画成十字。

## 二、七条关键检查点

| # | 检查项 | 反例 | 正例 |
|---|---|---|---|
| 1 | 唯一「开始」与「结束」 | 图中有两个六边形入口 | 一个 start，出口收敛到 1~2 个 end |
| 2 | 菱形必须两路 | 菱形只有一条出边 | 是 / 否 两条，且汇聚 |
| 3 | 是走上/下，否走左/右 | 否向上折返 | 是走下方端口，否走右侧端口 |
| 4 | 箭头不得回调执行顺序 | 用箭头直接把第 5 步接回第 3 步表示「重来」 | 加判定框，用回流边回到判定 |
| 5 | 同类符号等大小 | 判定框大小不一 | 同类符号同一尺寸（渲染器保证） |
| 6 | 连线正交、不无故弯曲 | 斜线、S 形绕行 | 只有横竖两向 |
| 7 | 单入口单出口、每路径只有一个箭头 | 一条线画两个箭头 | 一段线一个箭头 |

## 三、常见错误对照

| 错误写法 | 问题 | 改法 |
|---|---|---|
| 判定框里写「判断是否已登录」 | 不是问句，无法分流 | 「已登录？」+ 是/否 两出口 |
| 分支箭头不标注 | 读者不知道走哪条 | 每条出边标 是/否/条件值 |
| 处理框写三行说明文字 | 字多到看不清 | 压成 ≤12 字动词短语，说明移到批注 |
| 一个菱形挂 7 条分支 | 连线必然交叉 | 拆成两级判定，或改「主流程 + 子流程」 |
| 跨页用长箭头硬连 | 图被拉成一条长带 | 用连接符（出口五边形 / 入口圆形），编号对应 |
| 两条分支各自结束 | 出口发散 | 汇聚到同一节点后再结束 |
| 循环不写终止条件 | 死循环 | 菱形必须有非回流出口 |
| 用颜色表达「重要/次要点」 | 语义污染 | 颜色只按符号类别分配 |

## 四、交付前自检（按顺序逐条打勾）

渲染完先跑校验，再肉眼核这 8 条：

- [ ] `--check` 输出 **错误 0**
- [ ] 有且仅有一个「开始」；结束节点 ≤2
- [ ] 每个菱形都有 ≥2 条出边，且**每条都带标注**
- [ ] 分支最终都汇聚，没有悬空出口
- [ ] 循环有终止出口，回流边是虚线/清晰绕行
- [ ] 无文字被框边裁切、无标签压线
- [ ] 交叉处是「小半圆跨线」，不是十字交叉
- [ ] 同类符号大小一致、上下左右对齐（渲染器保证，肉眼复核一遍）

## 五、美化要点（学术版）

- **不填色**：白底黑线，元素靠形状与线宽区分；黑白打印、灰度复印都不丢信息。
- **线宽克制**：框线 1.25px、连线 1.1px，同一张图只用这两档；加粗会显脏。
- **箭头开口**：细线开口箭头（V 形），不用实心三角——实心箭头在缩小时糊成一团。
- **对齐**：同一列的框中心线必须重合——渲染器按列网格计算，无需手调。
- **疏密**：行距一致；分支密集处优先横向展开，纵向拉长会让主次不清。
- **留白**：图题与流程之间留 30px 以上；无图例时底部留白略等于左右边距。
- **长图**：超过 15 个节点或纵向超两屏时，拆成「主流程图 + 子流程图」，用 `predefined` 与 `connector` 衔接。
