# 绘制标准与自检清单

## 一、五条图形标准（逐条对齐）

1. **用「开始/结束」图形作为整个流程的开始和结束。**
   全图有且只有一个开始（黑色胶囊，写「开始」），出口收敛到 1~2 个结束（「结束」或结果态，如「登录成功」）。开始无入边，结束无出边。

2. **用「流程」图形描述某一个特定的流程。**
   绿色矩形，一个框只做一件事，写动词短语（「校验密码」「写入订单」），≤12 字。不要把三件事塞进一个框，也不要写整句说明。

3. **用「数据」图形描述某个数据信息。**
   橙色平行四边形。凡是「给人看/给人填/系统间传」的东西都归这里：提示消息（「提示账号不存在」）、单据（「采购审批单」）、报表、接口报文。**写名词或消息内容，不写动作**。

4. **用「判定」图形对多走向节点做判定。**
   蓝色菱形，框内必须是问句并以「？」结尾（「是否注册？」），至少两条出边，**每条出边都必须标注**（是/否、Y/N、账号错误、库存 > 0…）。三条以上纯多值分支要有「默认」兜底。

5. **用「连线」把上一个流程接到下一个流程，并描述动作与判定条件。**
   灰色箭头，正交走线，不穿框、不画十字（交叉处画小半圆跨线）。连线上必须写清楚这一步「做了什么」或「因为什么走这里」：`点击登录`、`提交`、`账号错误`。空白连线等于没画。

## 二、排版铁律

1. **单一入口、单一出口**：主流程只保留一条向下主线。
2. **流向一致**：一律自上而下、自左而右；折返必须走左侧车道，方向清晰。
3. **文字精炼**：框内写短语，不写句子；说明进批注。
4. **分支必标注**：菱形每条出边都有标签，绝不空白。
5. **避免线线交叉**：优先重排；无法避免时画「小半圆跨线」，不要画成十字。
6. **同类图形等大**：同类符号同一尺寸（渲染器保证）。

## 三、常见错误对照

| 错误写法 | 问题 | 改法 |
|---|---|---|
| 把「提示密码错误」画成绿色矩形 | 提示是数据，不是处理 | 改 `data`（橙色平行四边形） |
| 判定框写「判断是否已登录」 | 不是问句，无法分流 | 「已登录？」+ 是/否 两出口 |
| 处理框写「是否注册？」 | 该分流的节点画成了动作框 | 改 `decision`（W21 会提示） |
| 分支箭头不标注 | 读者不知道走哪条 | 每条出边标 是/否/条件值 |
| 流程之间连线无标签 | 看不出这一步做了什么 | 标动作：「点击登录」 |
| 一个菱形挂 7 条分支 | 连线必然交叉 | 拆两级判定，或改「主流程 + 子流程」 |
| 跨页用长箭头硬连 | 图被拉成一条长带 | 用连接符，编号对应 |
| 两条分支各自结束 | 出口发散 | 汇聚到同一节点后再结束 |
| 循环不写终止条件 | 死循环 | 菱形必须有非回流出口 |
| 用颜色表达「重要/次要点」 | 语义污染 | 颜色只按图形类别分配 |

## 四、交付前自检（逐条打勾）

- [ ] `--check` 输出 **错误 0**
- [ ] 有且仅有一个「开始」；结束节点 ≤2
- [ ] 每个菱形都有 ≥2 条出边，且**每条都带标注**
- [ ] 流程之间的连线都写了动作，没有空白箭头
- [ ] 所有提示/消息/单据都用了 `data`（平行四边形），没有误画成矩形
- [ ] 分支最终都汇聚，没有悬空出口
- [ ] 循环有终止出口，回流边是虚线并走左侧车道
- [ ] 无文字被框边裁切、无标签压线
- [ ] 交叉处是「小半圆跨线」
- [ ] 交付物是 **Mermaid 源码（贴进回复）+ SVG（present_files）**，没有 HTML

## 五、美化要点（standard 版）

- **颜色只表类别**：黑=起止、绿=流程、橙=数据、蓝=判定、灰=连线。不要再加第五种含义。
- **线宽克制**：框线 1.4px、连线 1.5px，全图只用这两档。
- **留白**：图题与流程之间 ≥30px；底部留白略等于左右边距。
- **长图**：超过 15 个节点或纵向超两屏时，拆「主流程图 + 子流程图」，用 `predefined` 与 `connector` 衔接。
