# 四大基本结构与画法

流程图的一切逻辑都归约为四种结构。动笔前先判定「这段逻辑属于哪一种」，再套用对应画法，不要边画边想。

## 1. 顺序结构（Sequential）

- **规则**：自上而下，一条主线。
- **画法**：`[处理 A] → [处理 B] → [处理 C]`
- **要点**：整条主线只允许一条竖线；若两个处理之间需要说明，用批注，不要插入额外方框。

```json
"edges": [
  {"from": "a", "to": "b"},
  {"from": "b", "to": "c"}
]
```

## 2. 条件 / 选择结构（If-Else）

- **规则**：一进两出。进入菱形后必须有两条出边。
- **画法**：菱形**下端口**引「是」，**右端口**引「否」。
- **要点**：两个分支最终必须汇聚到同一个后续节点上；「否」分支不能悬空结束。

```json
{"from": "d1", "to": "yes_node", "label": "是"},
{"from": "d1", "to": "no_node",  "label": "否"}
```

分支汇聚：两个分支的末端都指向同一个节点，渲染器会把右侧分支从**目标右侧**汇入，避免横穿主干。

## 3. 分支结构（Switch-Case / 多条件）

- **规则**：一个决策点，多个并列走向。
- **画法**：菱形右侧引出多条横线，各自下折进入对应处理框，最后全部汇聚。
- **要点**：
  1. 必须有一个「默认」或「其他」分支兜底，否则判定覆盖不全；
  2. 分支超过 5 个时，改用「主流程 + 子流程」拆分，一张图里不要出现 6 条以上的并列分支。

```json
{"from": "d", "to": "b1", "label": "待付款"},
{"from": "d", "to": "b2", "label": "待发货"},
{"from": "d", "to": "b3", "label": "已完成"},
{"from": "d", "to": "b4", "label": "默认"}
```

## 4. 循环结构（Loop）

### 4.1 当型循环（While，先判断后执行）

菱形在上，循环体在下；循环体结束后用虚线箭头**折返**到菱形上方。

```json
{"from": "d", "to": "body", "label": "是"},
{"from": "body", "to": "d", "label": "折返", "back": true, "style": "dashed"},
{"from": "d", "to": "after", "label": "否"}
```

### 4.2 直到型循环（Do-While，先执行后判断）

循环体在上，菱形在下；菱形「是」折返到循环体，「否」向下继续。

```json
{"from": "body", "to": "d"},
{"from": "d", "to": "body", "label": "是", "back": true, "style": "dashed"},
{"from": "d", "to": "after", "label": "否"}
```

- **回流边必须显式写 `"back": true`**。渲染器会把它画到左侧车道并自动升空绕行，不会横穿其他符号；未标注时也会自动识别并给出 W14 提示。
- **禁止死循环**：菱形必须有另一条非回流的出口（校验器 E09 会拦）。

## 结构组合的判定表

| 需求特征 | 结构 | 关键动作 |
|---|---|---|
| 甲做完做乙 | 顺序 | 一条竖线 |
| 满足条件才做，否则跳过 | If-Else | 是走下方，否走右方，末了必汇聚 |
| 按类型分头处理 | Switch-Case | 必须有默认分支 |
| 重复直到满足条件 | While / Do-While | 回流边 `back:true`，且有终止出口 |
| 逻辑超过 15 个节点 | 拆图 | 主流程 + 子流程（`predefined` 引用） |
